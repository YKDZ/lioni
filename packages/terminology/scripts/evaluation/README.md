# 术语评测

质量评测只接收显式输入，不指定默认数据集，也不维护数据集注册表。业务算法和计分不依赖输入的 `dataset.id`；该字段仅原样保留在报告中。

## 单个输入与批量输入

从仓库根目录使用 `pnpm --filter @lioni/terminology evaluation:quality`，或使用根命令 `pnpm terminology:evaluation:quality`。相对路径均从术语包目录解析；也可以传绝对路径。

- `--input 文件.json`：评测一个已整理的发现或 QA 输入；不指定 `--output` 时向标准输出写报告。
- `--input 输入目录 --output 报告目录`：递归评测输入目录中的 JSON，每份输入分别计分，报告保留输入的相对路径。目录为空或输入不合法时失败。输出目录必须位于输入目录之外，避免再次读取报告。
- `--max-words`、`--max-characters`、`--min-occurrences`、`--limit`：可显式覆盖发现参数；默认沿用各输入中的配置。

目录和文件名决定读写路径，数据集 ID 不参与路径计算。不同输入即使 ID 相同也不会共用报告。候选发现仍使用正式 `discoverTerms`；QA 仍使用正式分析与判断。报告保留输入摘要、参考答案身份、实际生效参数与计分结果；原文和参考答案保留在 `inputs/`。

## 一个评测一个目录

本地外部语料在包内 `corpora/`，整个目录被 Git 忽略。自有评测在本目录的 `cases/`，其输入与说明被跟踪，运行报告被忽略。每个评测独占自己的内容：

```text
某个评测/
  README.md
  inputs/
    development/    # 需要分组时使用
    validation/
  reports/
    baseline/
    current/
```

没有分组的评测可将输入直接放在 `inputs/`。输入文件自身包含参数及参考答案。历史报告、来源与许可说明留在所属评测目录。删除一个评测目录即可移除该评测，其他评测与包测试不会读取它。

通用代码只处理共同数据契约，不包含特定外部语料的下载、转换或 ID 分支。一次性整理所需的临时辅助内容与所属本地语料一起忽略，不进入通用脚本。单元测试使用自身拥有的合成 fixture，不借用可删除的评测数据。

## 性能基准

`pnpm terminology:evaluation:performance -- --output 报告绝对路径.json` 运行固定种子的合成负载，并通过独立子进程加载生产构建制品。该基准不读取外部语料或 `.scratch`；输出位置由调用方决定。
